팀장 의사결정 메모

결정 제안: 첫 출시는 사진 카드·애니메이션 중심이 아니라, 품목·수량·저장 상태가 한 화면에 보이는 목록 방향으로 진행한다. 사진 시안이 더 보기 좋다는 내부 의견은 비교 관찰로 확인된 사용성 근거가 아니다. 창고에서 12곳 중 7곳이 자주 끊긴다는 조건에서는 작업 중인 품목과 저장 여부를 한눈에 확인하고, 재접속 뒤 미완료 작업을 찾을 수 있는 것이 우선이다. 브랜드 느낌은 색·타입·작은 이미지 등 목록에 적용 가능한 요소로 살린다. 정확성·속도·현장 수용성 우선순위는 아직 합의되지 않았다. 이 제안은 저장 정확성과 실패의 가시성을 출시 관문으로 두고, 이후 관찰로 작업 속도와 수용성을 확인하는 잠정안이다.

첫 출시 범위와 직원 흐름

1. 공유 단말에서 스캔하면 목록에 품목명(식별 불가 시 바코드), 수량, 상태가 나타난다. 같은 바코드가 다시 들어오면 새 행을 만들지 수량을 늘릴지 먼저 결정할 제품 규칙을 정하고, 수량 변화는 저장 전에 직원이 확인·수정할 수 있게 한다. 인식이 불확실하거나 중복 가능성이 있으면 자동 확정하지 않고 확인을 요구한다.
2. 수량을 고친 뒤 저장을 누르면 즉시 완료로 표시하지 않는다. 서버 응답을 기다리는 동안 해당 행에 “저장 중”을 표시하고 중복 저장을 막는다. 확인 응답을 받은 뒤에만 “저장됨”으로 바꾼다. 실패·연결 끊김이면 “저장 안 됨 · 재시도 필요”를 표시하고 수정 내용을 화면에서 유지한다. 유지가 검증되기 전에는 앱 종료 시에도 보존된다고 약속하지 않는다.
3. 연결이 끊기면 상단에 “연결 끊김 · 저장 대기 N건”을 표시한다. 대기 항목을 식별하고 재시도할 수 있게 한다. 재접속 시 “연결됨 · 저장 재시도 중”을 표시하고, 각 항목을 서버 확인 뒤 “저장됨”으로 바꾼다. 충돌이나 결과 불명은 임의로 덮어쓰지 않고 “변경 충돌 · 확인 필요” 또는 “저장 확인 안 됨 · 다시 확인”으로 남겨 직원이 두 값을 비교·선택하거나 책임자에게 넘길 수 있게 한다. 재시도는 중복 반영을 만들지 않는지 검증해야 한다. 앱 재시작 뒤 대기 건이 복구되는지도 시험 전에는 보장하지 않는다.

8개발일의 우선순위

- 1일: 저장·재시도·중복 바코드·충돌의 동작 규칙과 상태 문구 합의, 실패 사례 설계.
- 2일: 목록형 핵심 화면, 스캔 후 품목 식별과 수량 수정 흐름 구현.
- 3~4일: 서버 응답 전 완료 표시 제거, 저장 대기·성공·실패 상태, 오프라인 입력 보존과 재접속 재시도 구현. 저장 확인의 근거와 재시도 중복 방지 방식을 정한다.
- 5일: 같은 품목을 두 단말에서 고치는 충돌 처리와 재시작 복구 경로 구현 또는 해결되지 않은 경우 안전한 보류·표시 구현.
- 6일: 끊김·지연·앱 재시작·반복 스캔·두 단말 충돌의 핵심 점검, 발견 문제 수정.
- 7~8일: 두 점포 관찰에서 나온 중대 장애 수정, 출시 판단 및 짧은 직원 안내 준비.

애니메이션, 사진 중심 카드 전면 구성, 광범위한 대시보드와 비핵심 편의 기능은 첫 범위에서 제외한다. 오프라인 저장, 재시작 복구, 충돌 해결이 일정 안에 검증되지 않으면 기능을 숨기고 안전한 출시로 간주하지 않는다. 4/20 유실 기록은 내부 점검에서 20건 중 4건이 사라졌다는 뜻일 뿐, 현장 유실률이나 예상치가 아니다. 특히 재시작 복구와 동시 수정은 미확인 위험으로 남는다.

관찰 2회와 판단 기준

다음 주 연결이 불안정한 점포를 우선 포함해 직원이 평소 방식으로 바코드 스캔→수량 수정→저장을 하도록 각 30분 관찰한다. 교육 전후 차이를 섞지 않도록 각 세션에서 직원의 기존 익숙함을 기록하고, 동의된 시험 데이터로 연결 끊김, 재접속, 앱 재시작, 같은 품목의 다른 단말 수정 상황을 짧게 재현한다. 관찰자는 개입하지 않고 완료 여부, 걸린 시간, 잘못된 품목·수량, 재시도/도움 요청, 저장 상태를 오해한 순간, 직원의 발언을 기록한다. 관찰 2회는 소규모 발견이지 대표 표본이나 오류율 추정이 아니다.

출시: 관찰에서 핵심 작업을 직원이 이해해 마치고, 성공 표시가 실제 확인과 일치하며, 끊김 뒤 대기 건이 유실·중복 없이 복구되고, 충돌이 조용히 덮어써지지 않음을 재현 시험으로 확인한 경우. 관찰 횟수만으로 데이터 안전을 입증했다고 보지 않는다.
보류: 저장 결과를 직원이 구분하지 못하거나, 재시작 후 건이 사라지거나, 재시도 중 중복 반영·잘못된 수량이 생기거나, 충돌 결과가 불명확한 경우. 원인 수정과 재검증 전 해당 흐름을 출시하지 않는다.
방향 변경: 두 세션 모두에서 목록이 스캔 품목을 찾거나 작업 맥락을 파악하는 데 지속적으로 방해가 되고, 실제 사진이 품목 식별 또는 수량 작업을 명확히 개선한다는 관찰 근거가 나오면 사진을 보조적으로 추가하거나 두 방향을 다시 비교한다. 보기 좋다는 선호만으로 전면 전환하지 않는다. 두 관찰의 결과가 엇갈리면 방향을 확정하지 않고 추가 관찰을 요청한다.

결정권과 재검토

팀장은 잠정 우선순위(정확성·속도·수용성)와 출시/보류 기준을 지금 승인한다. 제품·개발 담당자는 1일차에 저장 확인, 재시도 중복 방지, 바코드 중복 및 충돌 규칙을 명시하고 구현 가능성과 위험을 보고한다. 디자인 담당자는 목록 안에서 브랜드 표현을 제안하고 관찰 결과를 반영한다. 현장 담당자는 점포·직원 선정과 관찰 기록을 맡는다. 8일차에 팀장이 관찰 및 재현 시험 결과를 근거로 출시 여부와 화면 방향을 결정한다.

재검토 시점은 1일차 규칙 합의 때(충돌·복구 방식이 8일 내 검증 가능한지), 6일차 시험 뒤(유실·중복·충돌 미해결 여부), 7~8일차 관찰 뒤(작업 속도·수용성·방향 근거)로 정한다. 미해결 위험은 점포 확대 전에 다시 확인한다. 10분 교육 여건에 맞춰 스캔, 수량 수정, 상태 읽기, 재접속 후 확인만 담은 짧은 안내를 준비하되, 검증되지 않은 보존·동기화 동작을 안내에서 약속하지 않는다.
